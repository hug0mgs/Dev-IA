### Bug 1: Resolução de Protocolo
- O Bug: Quando o usuário clicava em "Entrar" ou em qualquer link de login, a URL gerada no navegador começava com http://, mesmo no ambiente de produção (Vercel) que usa HTTPS. Isso acontecia porque o código estava construindo a URL no client-side usando a variável de ambiente VERCEL_URL sem o prefixo público, fazendo com que o navegador interpretasse como http.

- A Solução do Agente: Focou em fazer a variável de ambiente chegar ao navegador. Trocou process.env.VERCEL por process.env.NEXT_PUBLIC_VERCEL_ENV, utilizando o prefixo obrigatório do Next.js para expor dados no client-side.

- A Solução dos Devs: Eliminaram a raiz do problema. Eles perceberam que não havia necessidade de consultar variáveis de ambiente no navegador para decidir o protocolo. Como a Vercel sempre força HTTPS, e o HTTP só acontece no ambiente de desenvolvimento local, a função getBaseUrl() foi reescrita para definir o protocolo de forma literal, dependendo do contexto de execução, ignorando variáveis no client-side.

- Análise: A solução do agente é correta do ponto de vista do funcionamento do Next.js. No entanto, a solução dos devs é superior porque simplifica o código e reduz a superfície de dependência de variáveis de ambiente.

### Bug 2: Redirecionamento de Login
- O Bug: Quando você acessa uma página que exige estar logado, o TabNews te manda para o /login e salva de onde você veio para te devolver para lá depois. Antes, o sistema usava uma variável fixa chamada baseUrl para tentar montar a URL completa de volta. A Vercel gera várias URLs para um mesmo projeto. Existe a URL oficial (tabnews.com.br), mas também existem URLs geradas automaticamente para cada branch. Como a baseUrl só conhecia uma origem oficial, se um programador fizesse login numa URL de teste, ele corria o risco de ser redirecionado para o site em produção ou a rota quebrar.

- A Solução do Agente: Foi pragmática e isolada. O agente modificou diretamente o componente da página de login (pages/login/index.jsx), montando a URL de volta concatenando os atributos: ${url.pathname}${url.search}${url.hash}.

- A Solução dos Devs: Foi modular e focada em segurança. Eles criaram uma função utilitária global chamada getSameOriginPath. Alteraram a função tryParseUrl para aceitar a raiz da URL (base) como segundo parâmetro. A nova função confronta o link com o location.origin (no navegador) ou o baseUrl (no servidor), extrai o caminho completo (path + search + hash) e retorna null se a origem for diferente.

- Análise: O agente consertou o bug visual, mas a abordagem dos devs resolveu um problema estrutural maior: ambientes de Preview da Vercel geram múltiplas URLs (aliases de branch). Centralizar essa lógica em getSameOriginPath e retornar null para origens desconhecidas protege o sistema contra ataques de Open Redirect de forma escalável.

### Bug 3: Preservação e Encoding de URL
- O Bug: Quando você era redirecionado para o login, partes importantes do seu link original eram apagadas.

- A Solução do Agente: Mapeou os 6 componentes do sistema que direcionavam para /login?redirect= e envelopou o router.asPath com encodeURIComponent.

- A Solução dos Devs: Fizeram exatamente a mesma modificação.

- Análise: Convergência total. Ambos aplicaram a prática padrão e correta do desenvolvimento web para evitar que caracteres reservados (?, &, #) da URL de destino quebrassem a estrutura da URL principal de login.
